# `all_req_list` 观测语义修复

## 问题

任务初始化会把全部入口及 robots/fuzz 扩展目标直接放入 `AllReqList`。这些 URL 即使没有被浏览器实际请求，也会出现在 `all_req_list`，并参与域名和子域统计，与“爬取过程中发现的请求”这一字段语义不符。

## 预期行为

- `Targets` 保存用户入口及路径扩展候选，用于 Scope 过滤和爬取调度。
- `AllReqList` 只记录浏览器页面实际观测到的请求，包括范围外资源。
- 范围外观测请求保留在 `AllReqList`，但不得进入 `ReqList` 或后续爬取队列。
- 去重、`AllDomainList` 和子域统计继续基于观测请求列表计算。

## 实施内容

1. 删除任务启动时将 `Targets` 复制到 `AllReqList` 的逻辑。
2. 页面请求继续先记录到 `AllReqList`，再通过现有 Scope filter 决定是否加入 `ReqList` 和队列。
3. 更新中英文 README 字段说明，并增加回归测试覆盖目标与观测结果分离、范围外请求保留及统计来源。

## 验收标准

- 未被浏览器请求的入口和扩展目标不会仅因作为爬取目标而出现在 `all_req_list`。
- 浏览器实际观察到的范围外资源出现在 `all_req_list`，但不进入 `req_list` 或爬取队列。
- 域名及子域名统计只使用去重后的观测请求。
